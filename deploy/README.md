# Размещение SparkSpace

Отдельный Compose-проект `sparkspace`, порт `127.0.0.1:18084`, каталог `/srv/projects/sparkspace`.

1. Выполнить `python tools/build_public.py`.
2. Поместить архив релиза в отдельный каталог `releases/<commit>/` на сервере.
3. Распаковать только статическую сборку и направить `current` на каталог релиза.
4. Запустить `docker compose -p sparkspace up -d --wait`.
5. Проверить контейнер через loopback, затем конфигурацию host Nginx через `nginx -t`.
6. Подключить HTTP-конфигурацию домена, изменить только A-записи SparkSpace на IP сервера. Почтовые MX/TXT сохранить.
7. После проверки DNS выпустить отдельный сертификат и включить HTTPS.

Для обновления или отката сменить `current` на выбранный каталог и пересоздать только службу `web`. Порт контейнера наружу не открыт. Контейнеры и данные остальных проектов не затрагиваются.

Ограничение текущей публикации: серверной формы заявок нет; доступны прямые контакты. Публикуются только файлы из release allowlist.

## Опубликованная конфигурация

- Канонический адрес: https://sparkspace.ru/.
- `www` и HTTP перенаправляются на канонический HTTPS.
- Отдельный сертификат Let's Encrypt с продлением через существующий Certbot.
- Текущий контейнер: `sparkspace-web-1`, порт только на loopback.
- DNS: корень и www указывают на сервер; MX/TXT сохранены.
- GitHub содержит исходники; GitHub Pages не используется.

После каждой публикации проверить страницы, изображения, контакты, сертификат и доступность соседних проектов. Сам push в GitHub пока не запускает автоматическое размещение.
