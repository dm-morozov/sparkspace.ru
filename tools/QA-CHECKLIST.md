# SparkSpace: повторяемая приёмка

Это сценарий проверки, а не отчёт об успешном прогоне. Все пункты изначально **UNRUN**. Заполнять для каждого релиза; локальная проверка не подтверждает публичную версию.

## Карточка прогона

- Дата / проверяющий: …
- Local URL / SHA / dirty-файлы / версия сборки: …
- Public URL / ожидаемый SHA / фактический серверный SHA / способ подтверждения: …
- Браузер, версия, ОС, устройство: …
- Requested viewport: …; actual `innerWidth × innerHeight`: …; DPR: …; browser zoom: …
- Ввод: мышь / клавиатура / эмуляция touch / физический touch: …
- Для каждого пункта: **LOCAL CHECKED / PUBLIC CHECKED / FAIL / UNRUN**, URL и состояние, actual viewport, факт, снимок или лог. Причину UNRUN записывать явно.
- Screen reader: название/версия и фактически прослушанные состояния либо UNRUN. DOM/ARIA-проверка не подтверждает озвучивание.

## Безопасность проверки

- Не отправлять реальные заявки, сообщения, письма; не звонить. У мессенджеров, mailto и tel проверять адрес и подпись, не запускать отправку.
- **Не читать и не перезаписывать пользовательский clipboard**, в том числе ради сохранения/восстановления. Не нажимать «Скопировать сообщение» в обычной пользовательской сессии.
- Clipboard проверять только в отдельном локальном тестовом контексте с заранее подменённым `writeText`, который отклоняет Promise и не обращается к системному буферу. Успешную ветку можно проверить отдельным no-op stub. Это fixture, а не проверка системного clipboard. Если изоляция недоступна — UNRUN. Не нажимать Ctrl+C в ручной ветке.
- Изменения browser-настроек, JS, reduced motion и stub делать в своей тестовой сессии; после прогона восстановить. Не менять пользовательские вкладки и общие настройки без согласования.

## 1. Геометрия и общий обход

- [ ] Запросить 320, 390, 768 и 1280 CSS px; каждый раз записать **фактическую** ширину. Неприменённый размер не засчитывать. Проверить главную, каталог услуг, одну типовую услугу, цены, оба кейса и контакты: нет горизонтального скролла, наложений, обрезанных CTA/подписей/фокуса.
- [ ] На главной проверить первый экран, направления, проекты, процессы и финальный контактный блок. Фото не растянуты, прозрачные иллюстрации не получают случайную рамку, изображения загружены, текст читается.
- [ ] Отдельно проверить настоящий browser zoom 200%: меню, цены/details, контакты и процессы. CSS-увеличение шрифта или text fixture записывать отдельно и не называть browser zoom.
- [ ] Для визуального сравнения сохранять одинаковые URL, actual viewport, zoom и состояние. Наличие одинаковых размеров DOM не заменяет просмотр снимков.

## 2. Меню и клавиатура

- [ ] Desktop: мышью навести на «Услуги», пройти зазор к ссылке; меню не закрывается по пути. Проверить обычный click и уход наружу. Эмулированный hover не называть физической мышью.
- [ ] С клавиатуры: Tab/Shift+Tab, Enter/Space на summary, переход по ссылкам; focus виден. Escape закрывает услуги и возвращает focus на summary.
- [ ] Mobile: открыть кнопку меню, затем услуги; первый Escape закрывает услуги, второй — меню с возвратом на кнопку. Проверить выход Tab из меню, отсутствие скрытых ссылок в Tab-порядке и доступность контактов.
- [ ] FAQ услуг и «Что входит в стоимость»: Enter/Space раскрывают нативные details; закрытое содержимое не перехватывает Tab. Проверить skip-link «К содержимому».

## 3. Процессы: пять отраслей × пять шагов

Отрасли: `sales`, `commerce`, `auto`, `property`, `content`. Прогнать каждую, фиксируя пропуски.

- [ ] Все пять шагов выбираются; подпись действия, роль, результат и вид руководителя соответствуют выбранному шагу и отрасли. Нет одновременно видимых экранов других шагов.
- [ ] На шаге 1 Back отключён. Next доводит до 5; на переходе 4→5 клавиатурный focus оказывается на доступном Back. Back доводит до 1; на 2→1 focus переходит на Next. Оба края без потери focus на BODY и без скачка страницы. Итого десять краевых переходов.
- [ ] «К началу» возвращает шаг 1. Перейти в другую отрасль и обратно: последняя позиция каждой отрасли сохраняется в пределах страницы; reset одной не сбрасывает остальные.
- [ ] Вкладки: стрелки влево/вправо, Home/End, Enter/Space; один tab-stop, видимый выбранный tab, соответствующий panel. В финале продаж проверить «Сделка / Позже / Отказ» и смену результата.
- [ ] На фактической ширине ≤540: «Вид руководителя» переносит к текущему экрану с focus; «Вернуться к шагу» возвращает именно выбранную кнопку. Обычный выбор шага не прокручивает автоматически. На desktop jump-кнопки скрыты и не попадают в Tab.
- [ ] При focus внутри manager сменить hash на другую отрасль: focus остаётся в видимой области, на выбранном tab. Проверить browser Back/Forward при наличии разных history entries; переключение вкладок само использует replaceState и не создаёт новую запись на каждый клик.
- [ ] Открыть `index.html?qa=1#flow-auto`: активен автосервис. Переключить отрасль: hash обновлён, `?qa=1` сохранён, нет принудительной прокрутки. Reload восстанавливает **отрасль**, не обещает сохранение шага после reload.
- [ ] `#flow-unknown` не ломает страницу; `#projects` работает как обычный якорь и не подменяется процессом. Неизвестные hash не вызывают исключений.

## 4. Цены, кейсы, обращение

- [ ] Цены, «от», состав и исключения совпадают на услуге и прайсе. Не считать «по задаче» фиксированной ценой. Выбор лендинга/сайта компании/магазина ведёт на contacts с соответствующим format.
- [ ] Оба кейса: настоящие desktop/mobile экраны читаемы, ссылка «Рассмотреть экран» открывает исходный файл в новой вкладке; focus виден, старый таб сохраняется. Подписи не обещают неподтверждённые результаты.
- [ ] Контакты: проверить видимые телефон, email, Telegram, MAX и href по утверждённым данным проекта. Ничего не отправлять. Публичная версия не должна содержать локальную API-форму или черновик согласия.
- [ ] `contacts.html?service=websites&format=landing` / `company` / `shop`: выбран правильный формат. `?service=automation&scenario=auto`: правильный процесс. Черновик редактируется; mailto содержит только публичный выбранный контекст, не текст пользователя.
- [ ] Неизвестные `service=unknown`, `format=unknown`, `scenario=unknown` и несовместимые `service=seo&scenario=auto`, `service=seo&format=shop` не отображаются как доверенные значения. Нет ошибок и вставки произвольной разметки. Пустой query оставляет общий вариант обращения.
- [ ] Только в clipboard fixture из раздела безопасности: отказ → textarea сфокусирована, текст выделен, понятная ручная инструкция, кнопка снова доступна. Пустой текст → предложение заполнить и focus textarea. No-op success → статус успеха; отдельно отметить, что реальное копирование не проверялось.

## 5. Отказы и предпочтения

- [ ] JS отключён: мобильное нативное «Меню сайта» открывается, ссылки доступны; процессы имеют статическое объяснение; FAQ и контакты доступны. Не требовать JS-интерактивность от fallback.
- [ ] Отдельно заблокировать только `script.js`: нативное меню остаётся доступным. Это другой сценарий, чем полное отключение JS.
- [ ] Reduced motion: контент виден сразу, reveal не оставляет пустые блоки, переходы не требуют анимации. Записать способ включения и фактическое значение media query.
- [ ] Screen reader, если доступен: выбранная отрасль/шаг, результат, раскрытые details и статус отказа копирования понятны, нет лишних повторов. Если не слушали — UNRUN даже при корректном aria-live.

## 6. Выпуск и откат

- [ ] До публикации: зафиксировать intended SHA, dirty-состояние, успешные проверки сборки/локальных ссылок, состав артефакта, предыдущий активный release и путь его сохранённой копии. Не подставлять старый SHA из прошлого отчёта.
- [ ] После разрешённой публикации: сверить активный серверный release/SHA с intended, состояние отдельного контейнера и HTTP. В публичном браузере подтвердить новые признаки версии с учётом cache; повторить меню, один процесс с обоими краями, кейс и контакты. Локальный PASS не переносится в PUBLIC CHECKED автоматически.
- [ ] У публичных страниц проверить canonical/title/description/social image, HTTP изображений и локальных шрифтов; отсутствие noindex и локальной API-формы. HTTP 200 не доказывает, что отдан нужный файл.
- [ ] План отката: записать предыдущий release, точный утверждённый механизм переключения и ответственного. Не выполнять откат ради отметки без разрешения. При реальном откате повторить проверку активного SHA, HTTP, меню и контактов; данные соседних проектов не затрагивать.
