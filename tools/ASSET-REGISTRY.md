# Реестр изображений SparkSpace

`design/asset-sources.json` — вручную проверенные сведения о происхождении. `design/asset-registry.json` — воспроизводимый снимок поставляемых растровых изображений и их использования. Файлы служебные, в public manifest не входят.

После обычной публичной сборки:

```powershell
backend/.venv/Scripts/python.exe tools/build_public.py
python tools/build_asset_registry.py --check
```

Вторая команда требует Python с Pillow и поддержкой используемых форматов. В текущей рабочей среде такой Python поставляется bundled runtime; Python backend может не иметь Pillow. Пакеты ради проверки автоматически не устанавливаются.

Если HTML изменился, сначала просмотреть подписи и страницы использования, затем обновить снимок:

```powershell
python tools/build_asset_registry.py
python tools/build_asset_registry.py --check
```

Если изменились байты существующего изображения, инструмент остановится даже при обычной генерации: сначала вручную проверить источник, дату съёмки, подписи и цены в кадре, затем обновить соответствующую запись sidecar и её `reviewed_sha256`. Нельзя просто переписать хеш ради зелёной проверки. Исходные изображения не удаляются.

`unknown` — неподтверждённое сведение, а не разрешение придумать источник или дату. Для реальных экранов дата относится к съёмке, для PageSpeed — к историческому desktop-отчёту. Ни один скриншот не подтверждает текущие цены или показатели. Генерации и композиции OG отделены от настоящих экранов. Хеш не доказывает авторство или отношения с заказчиком.

`--check` только читает. Он сверяет файлы, размеры, прозрачность, байты, источники и хеши всех публичных HTML. Поэтому даже текстовая правка страницы требует нового снимка после проверки. Поля `pages` учитывают img/source, picture/srcset, social metadata, favicon и ссылки на оригиналы; пустой список означает отсутствие таких ссылок, а не разрешение удалить ассет. CSS backgrounds и inline SVG в этот растровый реестр не входят.

Контроль ограничен содержимым текущей локальной публичной сборки; это не проверка CDN, серверного релиза, актуальности внешнего продукта или прав на изображение. Публичную публикацию подтверждать отдельно по `tools/QA-CHECKLIST.md`.
