# Источник стилей и порядок сборки

`design/style.css` — готовый артефакт, который читают страницы и локальный Docker. Не дописывать в него новые правила вручную: следующая HTML-сборка воспроизведёт его из источников.

`design/style-bundle.json` задаёт явную последовательность. Ранние правила до Stage29 сохраняются в `design/styles/legacy-base.css`. Поздние компоненты подключаются из соответствующих `stage*.css`; отдельные интеграционные правила остаются на прежних местах каскада. Порядок не определяется glob или номером Stage.

```powershell
python design/style_bundle.py --check
python design/build.py
python tools/build_public.py
```

Обычная сборка вызывает composer до вычисления CSS-версии. Если результат совпадает, файл не перезаписывается. Сначала читаются и проверяются все источники; отсутствие файла или недопустимый путь останавливает сборку. Composer не минифицирует, не сортирует и не удаляет правила. Проверка `--check` не должна изменять артефакт.

При правке позднего компонента изменять его source-файл из manifest и пересобирать HTML: ручное двойное редактирование больше не требуется. Ранние отдельные `stage25-*.css` и `stage35-fonts.css` остаются историческими справочными файлами; их содержимое пока включено в legacy-base, они не являются входами composer. Это частичное извлечение, а не полная очистка старого CSS.

Смешанные окончания строк унаследованы от проверенного артефакта и сохранены явно. `.gitattributes` отключает Git EOL-конверсию для CSS; не запускать массовое форматирование в этом техническом пакете. Новые фрагменты добавлять в manifest осознанно, после проверки всех страниц, использующих затронутые селекторы.

Локальный Docker не запускает генератор. Порядок работы: сначала host build, затем текущая сборка preview. Ни composer, ни исходные фрагменты не добавляются в публичный allowlist; на сервер отправляется только готовый CSS и остальные разрешённые ресурсы.

Public builder исторически дописывает свой блок `.public-enquiry` после копирования CSS. В Stage39 этот порядок сохранён побайтово; поэтому хеш публичного CSS отличается от локального. Отдельная задача в `Задачи.md` отслеживает полное покрытие публичной версии CSS fingerprint.
